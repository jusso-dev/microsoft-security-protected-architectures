# ISM Control Mapping

This document maps each core element of the Australian PROTECTED Microsoft Sentinel, Microsoft Sentinel data lake and Microsoft Defender XDR reference architectures to controls in the Australian Signals Directorate (ASD) [Information Security Manual (ISM)](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism).

- **ISM release referenced:** **September 2026** (verified against `cyber.gov.au` on **2026-11-21**)
- **Classification applicability:** All controls listed below apply to **PROTECTED (`P`)** environments (as well as other classifications noted in the ISM).

> **Disclaimer:** This is an independent community mapping for guidance only. It is not produced, endorsed or supported by ASD, ACSC or Microsoft. A mapping table is not a compliance attestation; every agency must confirm applicability, shared responsibility and residual risk against the current ISM release, Microsoft's latest Australia IRAP reports on the [Microsoft Service Trust Portal](https://servicetrust.microsoft.com/), and their IRAP assessor.

## Event logging and retention

Source: [ISM Guidelines for System Monitoring](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-system-monitoring).

| ISM control | Control summary (September 2026 ISM) | Architecture element | Implementation and evidence | Responsibility |
| :--- | :--- | :--- | :--- | :--- |
| `ISM-0580` | A security monitoring policy is developed, implemented and maintained. | Governance, ADRs and DCR baselines | Document logging scope, retention periods, alerting SLAs and review cadence; back implementation with [ADR-0002](../adr/0002-retention-analytics-tier-and-data-lake.md). | Agency |
| `ISM-1405` | A centralised event logging facility is implemented. | Primary Microsoft Sentinel workspace (Australia East or Australia Central) | Single primary Log Analytics workspace per PROTECTED tenant ([ADR-0001](../adr/0001-workspace-and-tenant-design-at-protected.md), [Single agency architecture](../architectures/single-agency-protected.md)). | Shared (Microsoft platform, Agency configuration) |
| `ISM-1983` | Event logs sent to a centralised event logging facility are sent as soon as possible after they occur. | AMA, DCRs, Syslog/CEF forwarders and native cloud connectors | Near-real-time streaming via [Azure Monitor Agent](https://learn.microsoft.com/en-us/azure/azure-monitor/agents/azure-monitor-agent-overview) and native cloud-to-cloud connectors; monitor ingestion latency and silent sources. | Shared |
| `ISM-1984` | Event logs sent to a centralised event logging facility are encrypted in transit using ASD-approved cryptography. | AMPLS, ExpressRoute (IPsec/MACsec), RFC 5425 Syslog over TLS | TLS 1.2/1.3 over [Azure Monitor Private Link Scope](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/private-link-design) and RFC 5425 TLS between appliances and Linux forwarders ([Hybrid architecture](../architectures/hybrid-and-on-premises-sources.md)). | Shared |
| `ISM-1985` | Event logs are protected from unauthorised access. | Defender Unified RBAC, Azure RBAC, AMPLS query restriction | Least-privilege role assignments ([Microsoft Sentinel roles](https://learn.microsoft.com/en-us/azure/sentinel/roles)), PIM just-in-time access, Conditional Access and private query endpoints. | Shared |
| `ISM-1815` | Event logs are protected from unauthorised modification and deletion. | Append-only Log Analytics workspace, Resource Locks, Azure Policy, WORM archive | Log Analytics tables are append-only; enforce `CanNotDelete` resource locks and Azure Policy blocking retention reductions; optionally mirror to immutable Blob Storage. | Shared |
| `ISM-0988` | An accurate and consistent time source is used for event logging. | Authoritative Australian NTP across servers, AD and network devices | Synchronise Domain Controllers, Azure VMs, Linux forwarders and network appliances to approved Australian NTP sources. | Agency |
| `ISM-1959` | To the extent possible, event logs are captured and stored in a consistent and structured format. | DCR KQL transformations and ASIM parsers | Apply DCR transforms at ingestion and normalise queries using Microsoft Sentinel Advanced Security Information Model (ASIM). | Agency |
| `ISM-1988` | Event logs are retained in a searchable manner for at least 12 months. | Sentinel Analytics (90d) mirrored to Sentinel data lake (or Log Analytics long-term retention) | Set minimum 365-day total retention across all security tables in the [Microsoft Sentinel data lake](https://learn.microsoft.com/en-us/azure/sentinel/datalake/sentinel-lake-overview) or Log Analytics archive ([ADR-0002](../adr/0002-retention-analytics-tier-and-data-lake.md)). | Shared |

## Monitoring, detection and threat hunting

Source: [ISM Guidelines for System Monitoring](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-system-monitoring).

| ISM control | Control summary (September 2026 ISM) | Architecture element | Implementation and evidence | Responsibility |
| :--- | :--- | :--- | :--- | :--- |
| `ISM-0120` | Cyber security personnel have access to sufficient tools to facilitate detection and incident identification. | Unified Microsoft Defender portal (Sentinel + Defender XDR + Workbooks + SOAR) | Unified SIEM and XDR console, Advanced Hunting, Workbooks and automated enrichment playbooks ([ADR-0003](../adr/0003-defender-xdr-integration-and-unified-soc-platform.md)). | Shared |
| `ISM-2116` | Cyber threat intelligence services are used to support detection and incident identification. | Sentinel Threat Intelligence connectors and TI analytics rules | Ingest curated threat feeds (including ASD Cyber Threat Intelligence Sharing where eligible) and correlate via Sentinel TI matching rules. | Agency / MSSP |
| `ISM-2117` | Suitable AI models are used to augment detection and incident identification. | Defender XDR correlation and Sentinel ML / UEBA (subject to IRAP scope) | Evaluate Microsoft Sentinel UEBA and AI-assisted features against current Service Trust Portal IRAP scope and `ISM-2112` before enabling on PROTECTED data. | Shared |
| `ISM-1986` | Event logs from critical servers are analysed in a timely manner to detect cyber security events. | AMA Windows/Linux security collection + Sentinel analytics rules | Ingest Domain Controller and critical server logs into Analytics tier with scheduled and NRT rules. | Agency / MSSP |
| `ISM-1906`, `ISM-1907` | Event logs from internet-facing and non-internet-facing servers are analysed in a timely manner. | Azure Arc + AMA + DCRs + Sentinel Analytics | Onboard Azure and on-premises servers via [Azure Arc](https://learn.microsoft.com/en-us/azure/azure-arc/servers/overview) and AMA with tailored DCRs. | Agency / MSSP |
| `ISM-0109` | Event logs from workstations are analysed in a timely manner. | Microsoft Defender for Endpoint + Defender XDR custom detections | Native XDR endpoint telemetry analysed in real time in the Defender portal and retained for 12+ months in Sentinel / Data Lake. | Shared |
| `ISM-1987` | Event logs from security products are analysed in a timely manner. | Defender XDR connectors, Azure Firewall, IPS/IDS and proxy connectors | Ingest alerts and deny logs from all security controls into Sentinel Analytics for unified correlation. | Shared |
| `ISM-1960`, `ISM-1961` | Event logs from internet-facing and non-internet-facing network devices are analysed in a timely manner. | HA Syslog/CEF forwarders + DCR split routing | Collect firewall, proxy, VPN and switch logs via [CEF/Syslog AMA](https://learn.microsoft.com/en-us/azure/sentinel/connect-common-event-format); alert on high-signal events in Analytics and hunt verbose allow logs in Data Lake. | Agency / MSSP |
| `ISM-1228` | Cyber security events are analysed in a timely manner to identify cyber security incidents. | Unified Defender portal incident queue and 24x7/business-hours SOC triage | Combine Sentinel analytics rules and Defender XDR alerts into prioritised incidents with defined triage SLAs. | Agency / MSSP |
| `ISM-2153` | Threat hunting activities, informed by current strategic and sector-specific cyber threat intelligence, are conducted at least every three months. | Sentinel Analytics (90d interactive) + Sentinel data lake KQL and notebooks | Run structured quarterly hunts across 90-day Analytics tables and 12-month data lake holdings using KQL jobs and notebooks. | Agency / MSSP |

## Access control, privileged environments and identity

Sources: [ISM Guidelines for System Management](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-system-management), [ISM Guidelines for System Hardening](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-system-hardening) and [ISM Guidelines for Personnel Security](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-personnel-security).

| ISM control | Control summary (September 2026 ISM) | Architecture element | Implementation and evidence | Responsibility |
| :--- | :--- | :--- | :--- | :--- |
| `ISM-1380` | Privileged human users use separate privileged and unprivileged operating environments. | Hardened SOC PAWs + Conditional Access device filters | Enforce dedicated Privileged Access Workstations for all Defender portal, Sentinel and Azure administrative sessions. | Agency / MSSP |
| `ISM-1687`, `ISM-1688` | Privileged operating environments are not virtualised within unprivileged ones; unprivileged accounts cannot log on to privileged operating environments. | Dedicated physical PAWs and Entra Conditional Access | Enforce hardware-backed PAWs and restrict logon strictly to dedicated privileged SOC identities. | Agency / MSSP |
| `ISM-1833` | User accounts are provisioned with the minimum privileges required. | Defender Unified RBAC, Azure RBAC and Azure Lighthouse | Assign scoped roles (`Microsoft Sentinel Reader`, `Responder`, `Contributor` only via PIM) and separate Tier 1 triage from detection engineering ([Update permissions with Defender RBAC](https://learn.microsoft.com/en-us/azure/sentinel/transition-unified-rbac)). | Agency / MSSP |
| `ISM-1952` | Privileged user accounts are not synchronised between Microsoft AD DS and Microsoft Entra ID. | Cloud-only Entra ID privileged accounts | Provision dedicated cloud-only Entra ID accounts for Azure, Sentinel and Defender portal administration rather than syncing on-premises Domain Admins. | Agency |
| `ISM-1939` | The number of accounts in highly privileged security groups is minimised. | Entra ID PIM eligible assignments and break-glass governance | Keep zero standing Global Administrators (except monitored break-glass accounts) and minimal PIM-eligible Sentinel/Security Administrators. | Agency |
| `ISM-1958` | User accounts with DCSync permissions cannot log on to unprivileged operating environments. | Active Directory Tier 0 + Defender for Identity monitoring | Enforce Tier 0 logon restrictions and monitor anomalous DCSync or directory replication via Defender for Identity. | Agency |
| `ISM-1565` | Tailored privileged user training is undertaken annually by all personnel with privileged access. | SOC and Sentinel administrator onboarding and annual refresh | Require documented annual privileged-user training before renewing PIM eligibility or Azure Lighthouse group membership. | Agency / MSSP |

## Networking, cryptography, incidents and outsourcing

Sources: [ISM Guidelines for Networking](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-networking), [ISM Guidelines for Cryptography](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-cryptography), [ISM Guidelines for Cyber Security Incidents](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-cyber-security-incidents), [ISM Guidelines for Procurement and Outsourcing](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-procurement-and-outsourcing) and [ISM Guidelines for Cyber Security Roles](https://www.cyber.gov.au/resources-business-and-government/essential-cyber-security/ism/cyber-security-guidelines/guidelines-cyber-security-roles).

| ISM control | Control summary (September 2026 ISM) | Architecture element | Implementation and evidence | Responsibility |
| :--- | :--- | :--- | :--- | :--- |
| `ISM-1181` | Networks are segregated into multiple network zones according to criticality. | Dedicated security subscription, hub VNet, AMPLS and collector VLANs | Isolate DCEs, Logic Apps Standard and Syslog forwarders in dedicated subnets/zones separated from general user workloads. | Agency |
| `ISM-1577` | An organisation's networks are segregated from their service providers' networks. | Azure Lighthouse and Defender MTO over HTTPS (no MSSP VNet peering) | Operate multi-tenant SOC access via unidirectional delegated control planes without bridging agency and MSSP VNets ([Multi-tenant architecture](../architectures/multi-tenant-mssp-protected.md)). | Agency / MSSP |
| `ISM-2068` | Internet connectivity for networked devices is strictly limited to those that require access. | AMPLS, Azure Arc Private Link and allow-listed egress proxy | Route AMA and Arc traffic over Private Link; allow-list only required Microsoft Defender sensor endpoints through inspected egress gateways. | Agency |
| `ISM-1080`, `ISM-1769` | ASD-approved cryptography (AES-256) is used when encrypting data at rest. | Azure platform AES-256 encryption (with documented CMK caveats) | Verify AES-256 encryption at rest in Australia IRAP reports; document CMK gaps for Sentinel data lake and Defender portal incidents ([Service availability and IRAP status](../docs/service-availability-and-irap.md)). | Shared |
| `ISM-0125`, `ISM-1819` | Cyber security incident register maintained and response plan executed upon incident identification. | Unified Defender portal incident queue and SOAR playbooks | Track every incident in Defender portal with immutable timestamps, owner history and approved Logic Apps playbooks; retain incident logs per records authority. | Agency / MSSP |
| `ISM-0133`, `ISM-0140` | Data spill containment and timely reporting of cyber security incidents to ASD. | SOC incident response playbooks and MSSP escalation runbooks | Include mandatory ASD reporting timelines and cross-agency spill procedures in SOC runbooks. | Agency / MSSP |
| `ISM-1637`, `ISM-1736` | Outsourced cloud service register and managed service register are maintained and regularly verified. | Cloud and MSSP governance registers | Record Microsoft Azure, Microsoft 365, Sentinel, Defender XDR and any MSSP SOC provider with current IRAP report dates and review cycles. | Agency |
| `ISM-1395`, `ISM-1451`, `ISM-1573`, `ISM-1804` | Provider protection, documented data ownership, access to all logs, and contractual break clauses. | Agency-owned PROTECTED tenant and revocable Azure Lighthouse delegation | Keep all telemetry in the agency's own Australian subscription and tenant; test immediate Lighthouse and GDAP revocation for contract exit. | Agency / MSSP |
| `ISM-1203`, `ISM-1525`, `ISM-1587` | System registration, threat and risk assessment and annual security reporting to Authorising Officer. | IRAP assessment package and ATO governance | Review current [Australia IRAP](https://learn.microsoft.com/en-us/azure/compliance/offerings/offering-australia-irap) reports on the Service Trust Portal and submit agency security risk management plan to the Authorising Officer. | Agency |
